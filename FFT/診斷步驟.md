## 步驟 1: 確認 FPGA 已重新編譯和燒錄 ⭐ 最重要

### 在 Quartus 中：
1. **開啟專案**
   - 確認開啟的是最新的 `fft_system_top.vhd`

2. **重新完整編譯**（不要用增量編譯）：
   ```
   Processing → Start Compilation（Ctrl+L）
   或分步驟：
   - Processing → Start → Start Analysis & Synthesis
   - Processing → Start → Start Fitter
   - Processing → Start → Start Assembler
   ```

3. **檢查編譯時間戳**：
   - 在 Quartus 訊息視窗查看編譯完成時間
   - 確認是最新的（在您拉取 GitHub 修改之後）

4. **燒錄到 FPGA**：
   ```
   Tools → Programmer
   - 確認 .sof 檔案是最新的
   - 勾選 Program/Configure
   - 點擊 Start
   - 等待 Progress 100% 和 "Successful"
   ```

5. **驗證燒錄**：
   - 燒錄後，FPGA 會自動重新啟動
   - 所有 LED 應該短暫閃爍然後復位

## 步驟 2: 強制 FPGA 復位

燒錄完成後：
1. **按下並釋放 reset 按鈕**（如果板子有）
2. 或者**重新上電**（拔掉USB，重新插入）
3. 確保 `rst_n` 訊號正常（LED 應該熄滅然後恢復）

## 步驟 3: 檢查 VHDL 修改是否生效

### 方法 A: 查看 RTL Viewer
1. Tools → Netlist Viewers → RTL Viewer
2. 找到 `START_FFT` 狀態的邏輯
3. 檢查是否有 `sample_idx <= 0` 的賦值

### 方法 B: 查看編譯報告
1. Processing → Compilation Report
2. 查看 Analysis & Synthesis → Resource Usage
3. 確認邏輯元素數量有變化（修改後應該略有不同）

如果FPGA問題難以解決，可以先測試通訊：

### 在 VB 端做 loopback 測試：
1. 將 TTL 轉換器的 TX 和 RX 短接
2. 執行 VB 程式發送
3. 應該立即收到相同的資料（1028 bytes）

這可以確認：
- VB 程式正常
- 串口轉換器正常
- 排除FPGA問題

## 常見問題排除

### Q: 編譯成功但資料沒變化？
A: 
1. 確認燒錄的是最新的 .sof 檔案（檢查時間戳）
2. 確認燒錄過程沒有錯誤訊息
3. 嘗試完全關閉 Quartus 後重新開啟並編譯

### Q: LED 繞一圈是什麼意思？
A: 表示 FSM 從 WAIT_H1 → ... → SEND_PAYLOAD → WAIT_H1 完成一個循環。
   這是**好消息**，表示 FPGA 在運作，但發送的資料不對。

### Q: 為什麼收到 931 bytes 而不是 1028 bytes？
A: 
- 1028 bytes = 2 (header) + 2 (length) + 1024 (payload)
- 931 bytes 表示傳輸中斷或buffer問題
- 可能是舊資料殘留在UART TX buffer中

### Q: `55-FD` 開頭是什麼？
A: 
- `0x55` 是正確的 TX_HEADER_H1
- `0xFD` = -3 (signed) 或 253 (unsigned)
- 這不是 header 的第二個byte（應該是 0xAA）
- 可能是：
  1. FPGA在header前發送了額外資料
  2. UART buffer中的舊資料
  3. 記憶體未初始化的值
