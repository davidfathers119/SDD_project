# 關鍵發現：FPGA未正確接收封包

## LED燈號診斷結果

### 觀察到的現象
1. LED[0] (rx_v) 亮 → UART 有接收到資料 ✓
2. LED[3] (fft_done) 一直亮 → FFT done 信號異常
3. LED[7] (RECV_PAYLOAD) **沒亮** → ❌ **關鍵問題！**
4. 其他LED都不亮

### 結論
**FPGA 根本沒有進入 RECV_PAYLOAD 狀態！**

FSM 停留在 WAIT_H1/WAIT_H2 等待正確的 header，但一直收不到。

## 資料分析

### VB 發送的封包
```
AA-55-00-01-[1024 bytes payload]
```
- Header: 0xAA 0x55 ✓
- Length: 0x00 0x01 = 0x0100 = 256 (little-endian) ✓

### FPGA 期望接收
```vhdl
RX_HEADER_H1 = 0xAA
RX_HEADER_H2 = 0x55
```

### 實際收到的資料
```
55-FD-FF-FF-FF-FF-F7-F7-FF-FF-...
```
- 第一個 byte: 0x55 (正確!)
- 第二個 byte: 0xFD (錯誤! 應該是 0xAA)
- 後續都是資料

## 問題根源

### 可能性1: UART Buffer 中的舊資料（最可能）
- FPGA 在開機或reset後，UART TX buffer 可能包含未初始化的資料
- 或者是之前測試留下的殘留資料
- FPGA 啟動後立即開始發送這些垃圾資料

### 證據
1. 資料開頭是 `0x55`（剛好是 TX_HEADER_H1）
2. 但後面不是完整的封包格式
3. 資料長度 843 bytes（不是 1028）
4. 資料有重複的 pattern（記憶體未初始化）

### 可能性2: FSM 未正確 Reset
- 上電或reset後，FSM 可能不在 WAIT_H1 狀態
- 可能卡在某個異常狀態開始發送

## 解決方案

### 方案 A: 增加 FPGA Power-On Reset 延遲 ⭐ 推薦

在 top module 增加 power-on reset 邏輯：

```vhdl
signal por_count : integer range 0 to 1000 := 0;
signal por_done : std_logic := '0';
signal rst_n_internal : std_logic;

-- Power-on reset: 等待一段時間後才開始
process(clk25)
begin
    if rising_edge(clk25) then
        if por_count < 1000 then
            por_count <= por_count + 1;
            por_done <= '0';
        else
            por_done <= '1';
        end if;
    end if;
end process;

rst_n_internal <= rst_n and por_done;
```

### 方案 B: 在接收到正確 header 前清空 TX

修改 WAIT_H1 狀態，在開始前不發送任何資料：

```vhdl
when WAIT_H1 =>
    -- 確保不發送任何東西
    tx_v <= '0';
    if rx_v = '1' then
        if rx_b = RX_HEADER_H1 then
            ps <= WAIT_H2;
        end if;
    end if;
```

### 方案 C: VB 端增加重試機制

在 VB 中，如果 timeout，自動重新發送：

```vb
For retry As Integer = 1 To 3
    Try
        Dim response = Await _service.SendAndReceiveAsync(...)
        ' 成功，跳出
        Exit For
    Catch ex As TimeoutException
        If retry < 3 Then
            Log($"[Retry] Attempt {retry + 1}/3")
            Thread.Sleep(500)
        Else
            Throw
        End If
    End Try
Next
```

### 方案 D: 手動清除 UART Buffer（臨時）

1. 在 VB 連接 COM 埠後，先讀取並丟棄所有資料：
```vb
_port.ClearBuffers()
Thread.Sleep(100)
_port.ClearBuffers()
```

2. 或者在 FPGA 板上按 reset 按鈕，然後立即執行 VB 程式

## 立即測試步驟

### 步驟 1: 驗證是舊資料
1. 重新上電 FPGA（完全斷電再上電）
2. 立即執行 VB 程式
3. 觀察：
   - 如果還是 843 bytes 且 `55-FD` 開頭 → 是記憶體未初始化
   - 如果資料不同 → 可能是隨機的

### 步驟 2: 強制 Reset
在 VB 發送前加入：
```vb
' 發送前等待 FPGA 穩定
_port.ClearBuffers()
Thread.Sleep(200)
_port.ClearBuffers()
```

### 步驟 3: 觀察 LED
如果修改後：
- LED[7] 應該亮起（進入 RECV_PAYLOAD）
- 然後 LED[4] 短暫亮起（START_FFT）
- 最後 LED[5] 和 LED[6] 亮起（發送）

## 建議的修正順序

1. **立即**: 在 VB 中增加 buffer 清除和延遲
2. **短期**: 修改 VHDL 增加 power-on reset
3. **中期**: 增加 VB 重試機制
4. **長期**: 完整實現 FFT 並替換 stub

## 關鍵觀察

收到的 843 bytes 資料是有規律的 pattern，這**不是**您發送的 1000Hz 正弦波！

這確認了資料來源：
- ❌ 不是 VB 發送的資料被回傳
- ✅ 是 FPGA 記憶體中的未初始化資料或舊資料

**結論**: FPGA 收不到正確的 header，所以 FSM 卡在 WAIT_H1/WAIT_H2，從未進入 RECV_PAYLOAD。同時，UART TX 可能自動發送了 buffer 中的垃圾資料。
